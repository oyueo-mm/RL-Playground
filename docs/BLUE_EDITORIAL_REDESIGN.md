## 1. 변경 전 디자인 문제

- 인터페이스 전체가 연녹색·세이지 계열이었다. CSS에 **214개의 서로 다른 녹색 계열 값**이 규칙마다 흩어져 있었고 토큰은 배경·표면·구분선 3개뿐이었다.
- 홈 화면은 제목 하나를 위해 브레드크럼, 상단 라벨, 슬로건, 두 문장 설명, 안내 문구, 알고리즘 칩 3개, 기능 바로가기 카드 3개, 3단 푸터를 쌓고 있었다. 제목보다 장식 텍스트가 많았고, 대부분은 사이드바와 핵심 버튼의 기능과 중복이었다.
- 작은 글자의 연한 회녹색(예: `#9aa690` 은 흰 배경에서 대비 **2.55:1**)이 AA 기준을 크게 밑돌았다.
- 홈 CSS에는 어디서도 쓰지 않는 규칙(과거 카드형 시연, 개념 카드, 알고리즘 섹션 등)이 남아 있었다.

## 4. 디자인 콘셉트

「단단한 강화학습」 표지의 **색채 체계와 타이포그래피 분위기만** 참고했다(흰 바탕, 거의 검정인 굵은 제목, 깊은 파랑, 절제된 사용). 표지 이미지나 일러스트는 쓰지 않았다.

- 홈은 큰 제목 하나와 시연 카드로 구성. 제목 첫 줄은 검정에 가까운 `#171A20`, 둘째 줄은 `#0754A5`. 글자 굵기 800, 자간 −0.045em, 행간 1.08, 한글은 `word-break: keep-all`.

- 그림자·그라데이션·글로우를 추가하지 않았다. 기존의 `primary-button` 그림자, 홈 시연 카드 그림자, 버튼 hover 상승 효과는 제거했다.

## 6. 색상 이전 방식

일괄 치환이 아니다. 녹색 계열 값을 (명도, 채도, **CSS 속성**) 기준 역할 규칙으로 변환했다: 글자색은 명도에 따라 `text-primary / text-body / text-secondary / navy / primary`, 테두리는 `line / line-strong / accent`, 배경은 `bg-app / surface-muted / hover / primary-soft / line / primary`, 반투명 그림자·백드롭은 네이비 같은 알파로 바꿨다. 이후 결과를 검토하며 수작업으로 보정했다 — 자동 규칙이 연한 회녹색 글자를 모두 파랑으로 보낸 경우(툴바·줌·접기 버튼 등)를 `text-body`로 되돌렸고, 사이드바 활성/hover 배경을 구분했다.

TSX의 인터페이스 색도 정리했다: 선택 셀 윤곽선, 미니맵, 드래그 미리보기 유효 색, 시연 경로선, Tailwind `bg-green-700`/`bg-teal-600`/`bg-purple-600` 버튼 → 파랑.

## 11. 남은 문제

- 프리셋 갤러리의 미리보기 PNG는 연녹색 배경이 내장된 이미지이며, 맵 디자인 보존 원칙에 따라 다시 만들지 않았다.
- 모바일 편집기에서 속성 패널이 열리면 격자가 작아진다(V4부터 있던 레이아웃으로 이번 범위 밖).
- 전체 단위 테스트 중 무거운 통합 테스트(`App.test.tsx` 등)는 병렬·고부하 상태에서 드물게 한 건씩 시간 초과로 실패한다. 단독 재실행에서는 통과하며 V4 때도 같았다.

## 13. 마감 개선 (라벨 제거 · 글자 크기 · 조작 컴포넌트 테두리)

**1) `30 WORLDS / EXPLORE` 제거.** 한국어·영어 모두 JSX에서 삭제. 시연 카드 머리에는 `설명용 시연` / `SCRIPTED DEMO` 배지만 남기고 오른쪽 정렬했다. 배지 글자는 8px → 11px.

**2) 작은 글자.** 정의 파일이 아니라 브라우저에서 *실제 렌더링된* 크기를 측정했다(홈·학습 환경+설정 탭+분석·편집기+속성·인스펙터·프리셋·결과(학습 후)·가이드, 데스크톱 1440 / 모바일 390). 가독성이 필요한 문구를 11px 이상으로 올렸다:

| 문구 | 전 | 후 |
|---|---|---|
| 툴바 속도 라벨·값(`속도: 보통`, `200 ms / 스텝`) | 9 / 8px | 11px (줄바꿈 허용) |
| 시연 배지 `설명용 시연`, 시연 카드 `난이도 · n/m` | 8 / 10px | 11px |
| 모바일 툴바 버튼(`학습하기` `일시정지` `설정` 등) | 10px | 11px |
| 프리셋 카드 요소·크기 줄, 선택한 프리셋의 `검증된 성공 경로` 등 `<small>` | 9 / 8.8 / 9.6px | 11px (전역 `small` 바닥값 `max(11px, .833em)`) |
| 가이드 단원 번호·라벨·목차 번호, 팔레트 구분 라벨, 연결 ID 표시, 시나리오 탭 | 8–10px | 10–11px |
| 결과 차트 막대 라벨·개수 | 11 → 렌더 9.4px | 12 → 렌더 10.2–10.6px |
| 보상·학습 진행 차트 축 눈금 | 7–8 → 렌더 5.7–8.9px | 10–11 (렌더 약 9–11px) |

레이아웃·정보 밀도는 유지했다. 모바일 툴바 속도 슬라이더 너비를 늘렸다가 `분석` 버튼이 다음 줄로 밀리는 것을 스크린샷에서 발견해 원래 너비(126px)로 되돌렸다. 결과 차트는 viewBox에 비례해 줄어들므로 패딩·좌표(테스트로 고정됨)를 건드리지 않고 글자 크기만 올렸다 — 일부 눈금은 렌더링 9px 안팎으로 10px 미만이다. 맵 안의 타일 라벨(포털·스위치 ID 등)은 격자와 함께 확대·축소되는 지도 그래픽이라 대상에서 제외했다.

**3) 조작 컴포넌트 테두리(WCAG 2.2 AA 1.4.11).** 새 토큰 `--control-border: #7A8696`: 흰색 3.70 · 배경 3.57 · 보조 면 3.44 · 연한 파랑 3.28 · hover 3.29 로 모든 바탕에서 3:1 이상. 적용 대상은 **경계가 조작 요소임을 알려 주는** 컨트롤뿐이다: 모든 입력창·`select`·`textarea`(전역 규칙 + Tailwind 클래스로 `--line`에 덮이던 알고리즘 선택 상자 수정), 윤곽선 버튼(`demo-playback`, 분석 헤더, 접기 버튼, 속성 패널 가져오기/내보내기, 시나리오·난이도·리소스 필터, 방향 패드, 이전/다음 장). 선택·눌림 상태의 테두리는 `--accent`(`#2479D8`, 4.37:1)이고, 입력 포커스 테두리는 `--primary`다.
**의도적으로 그대로 둔 것:** 장식 구분선·카드 테두리(`--line`, 1.25:1 — 테스트가 "2:1 미만 유지"를 단언), 프리셋 카드와 홈 시연 썸네일(이미지·글자로 식별되고 선택 상태는 2px accent 테두리), 비활성 버튼(WCAG 면제), 체크박스·라디오(브라우저 기본 + `accent-color`). 범위 슬라이더는 파란 채움과 손잡이로 식별되며 안 채워진 트랙 색은 바꾸지 않았다.

**검증.** 측정 스크립트로 모든 화면의 입력·선택·윤곽 버튼 테두리 대비를 계산했고 위 예외 외에는 모두 3:1 이상이다. 같은 검사를 E2E(`e2e/blueRedesign.spec.ts`)에 넣어 홈·학습 환경·설정 탭·편집기 속성·인스펙터·프리셋·가이드 계산기에서 데스크톱과 모바일 각각 "11px 미만 HTML 글자 0건, 3:1 미만 입력 테두리 0건"을 단언한다. 단위 테스트가 `30 WORLDS` 부재와 `설명용 시연` 유지(한·영)를 단언하고, 스타일시트에 10px 미만 글자가 없으며 `--control-border`가 모든 면에서 3:1임을 단언한다. 전후 스크린샷: `docs/screenshots/blue-polish/`.

| 항목 | 결과 |
|---|---|
| 린트 · `tsc -b` · 빌드 | 통과 |
| 단위 테스트 | 85개 파일 · **1,499 통과** |
| Playwright E2E | **75 통과 · 5 건너뜀 · 실패 0** |

남은 한계: 차트 눈금 일부와 8px 안팎의 지도 SVG 라벨은 렌더링이 10px 미만이다. 슬라이더 트랙의 비텍스트 대비는 손잡이·채움에 의존한다. 공식 프리셋 30개와 모든 기능은 변경하지 않았고 해당 테스트가 모두 통과한다.
