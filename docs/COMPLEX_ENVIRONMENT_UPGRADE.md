# 복잡한 환경, 편집기 및 홈 UI 개선

검증일: 2026-10-25. 브랜치: `feat/home-redesign`. 시작 기준은 원격과 일치한 `0242a04`다.

## 1. 전체 변경 사항

- 이론 상태 공간에 의한 적용 거부를 제거하고 구조 오류와 복잡도 경고를 분리했다.
- 희소 Q-table을 유지하며 실제 생성 행, 저장 스텝, 처리율, UI 갱신 빈도와 메모리 추정치를 계측한다.
- React에는 현재 격자에 필요한 Q 행만 불변 투영하고, UI 주기와 학습 실행을 분리했다.
- 실제 자원 예산 일시정지와 별도 `truncated` 에피소드 종료를 추가했다.
- 좌표 인덱스·증분 BigInt 마스크·정적 지형 캐시·숨긴 패널 렌더 유예·큰 그래프 표시 제한을 적용했다.
- SVG 도구, 드래그 이동, 원자적 덮어쓰기, 자동 포털/그룹 ID를 기존 100단계 Undo/Redo에 연결했다.
- 가이드의 제목까지 하나의 본문 흐름으로 스크롤하고 홈을 간결한 2열과 기능 링크로 정리했다.
- 실제 환경 규칙을 재사용하는 홈 시나리오 5종과 해결 경로를 검증한 대형 프리셋 9종을 추가했다.

Q-Learning/SARSA 업데이트, 기존 상태 키 의미, Goal/Bomb·동적 지형 규칙, 기본 250 에피소드, 기존 16개 맵, JSON v1/v2, 언어·화면 전환 상태 보존을 유지했다.

## 2. 기존 제한의 원인

`validateFeatures()`는 `cells × 2^(Goal + Fragile + Toggle 그룹)`의 상한이 262,144를 넘으면 오류를 반환했다. 이는 방문한 Q 상태 수가 아닌 가능한 조합 수라서, 희소 Map으로 충분히 실행 가능한 맵도 거절했다.

현재 `STATE_SPACE_WARNING=262_144`는 정보성 경고 기준일 뿐이다. 검증 오류 목록에는 포함하지 않으며 실제 생성 행은 초기 0개다. 큰 유효 맵을 편집기·JSON·엔진 경계에서 적용하고 실행하는 테스트를 추가했다.

## 3. 환경 적용 및 복잡도 표기

구조 오류는 계속 차단한다. 좌표·방향·크기·Start/Goal·중복·포털 두 끝점/고유 ID·그룹 연결·지원 JSON 형식을 검증한다. 편집기와 import는 같은 검증 경계를 사용한다. 새 요소 맵의 기본 지형 좌표와 중복도 검사한다.

`stateSpaceDetails()`는 Goal/Fragile/그룹 개수, 로그 기반 크기와 안전한 표기를 제공한다. 안전 정수 안에서는 BigInt로 정확한 수를 표시하고, 그보다 크면 `≈ 4.12 × 10^…` 형태를 사용한다. 잘못된 크기의 편집 중 입력도 NaN/Infinity 대신 ‘—’로 표시한다. 기존 수치 추정 API도 남겨 두었다.

복잡도 경고는 ‘적용 가능하며 실제 생성 Q 행을 기준으로 관리한다’고 명시한다. 실제 Q 행 수와 이론 조합 상한은 서로 다른 레이블을 사용한다.

## 4. 희소 Q-table·스냅샷·전이 최적화

`Map<StateKey, number[]>`와 lazy 생성은 그대로다. 상태의 Goal/Fragile/그룹 비트를 생략하거나 서로 다른 상태를 병합하지 않는다. 생성 행 수, 키 문자 수와 변경 revision을 별도 계측한다.

기존 `getSnapshot()` 및 전체 `subscribe()`는 명시적인 전체 검사 API로 유지한다. 일반 React 경로는 `getUISnapshot()/subscribeUI()`를 사용한다. 현재 동적 상태 suffix에 대해 최대 width×height개 좌표와 일치하는 행을 직접 조회한다. 조회는 없는 행을 생성하지 않는다. 각 벡터와 Q record는 복사·freeze되며 revision/전체 행 수/visible scope가 명시된다. 변경 가능한 Map 자체를 React에 전달하지 않는다.

환경 모델·통계·TD 정보·Q 투영은 같은 동기 읽기 시점에서 구성한다. 이력 배열은 에피소드가 늘거나 환경이 초기화될 때만 새 UI 복사본을 만든다. 전체 스냅샷은 계속 방어적 복사를 제공한다.

전이에서는 벽/Bomb/Goal/포털/방향/Fragile/스위치/그룹 벽을 생성 시 Set/Map으로 인덱싱한다. Goal/Fragile/그룹의 BigInt 마스크는 실제 변화 때만 갱신한다. 지형 렌더 배열은 에이전트 위치만 바뀌면 재사용한다. `setConfig()` 시 인덱스와 비트 순서도 재구축하고, 입력 설정 및 getConfig 결과를 분리해 외부 배열 변경으로 인덱스가 어긋나지 않게 했다.

고속 배치는 스텝 경계에서 **8ms 작업 목표**에 도달하면 다음 프레임에 이어서 실행한다. 학습 스텝·보상·TD 업데이트는 건너뛰지 않는다. UI 발행은 보통 80ms 간격, 높은 실제 사용량에서는 250ms 간격이다. 첫 배치와 Pause/Resume/Stop/설정 변경은 즉시 발행한다.

숨긴 분석·편집 패널은 마운트를 유지한 채 렌더를 유예한다. 정적 격자와 그래프의 불필요한 렌더를 줄였다. 매우 긴 보상/진행 그래프는 **최대 800개 표시점**을 사용하되 양 끝점·선택점·전체 최솟값/최댓값을 포함한다. 전체 에피소드 데이터와 학습 수학은 그대로이고 표시 표본임을 안내한다. 15만 에피소드 그래프의 인자 스택 초과/무제한 DOM 생성을 회귀 테스트했다.

### 동일 조건의 반복 엔진 실행

로컬 Microsoft Edge에서 7×7, 14×14, 20×20 맵을 **각 10초씩 2회**, 전후 각각 총 약 60초 실행했다. 고정 난수 seed, α=0.1/γ=0.9/ε=0.3, 100 steps/frame다. 변경 전은 전체 구독, 변경 후는 UI 구독을 사용한다. 비교를 위해 변경 후 에피소드 제한은 100만으로 높여 표본 중 truncation이 일어나지 않게 했다. 매초의 명시적 전체 스냅샷 조회 비용도 원시 표본에 포함된다. 이 측정은 엔진 구독 경로이며 React 렌더 벤치마크와 구분한다.

| 맵 | 전: steps/s 두 번 | 후: steps/s 두 번 | 생성 Q 행 전/후 | 완료 에피소드 전/후 |
|---|---:|---:|---:|---:|
| 7×7 | 6,021 / 6,002 | 6,006 / 6,011 | 48 / 48 | 3,443 / 3,439 |
| 14×14 | 6,004 / 6,019 | 6,020 / 6,005 | 3,346 / 3,346 | 112 / 112 |
| 20×20 | 6,018 / 6,011 | 6,010 / 6,016 | 3,135 / 3,135 | 47 / 47 |

100 steps/frame와 약 60Hz 스케줄링 상한 때문에 처리량은 대체로 같다. 큰 학습 속도 향상을 주장하지 않는다. 10초당 구독 이벤트는 전 607–610회에서 후 124–125회로 줄었다. 이는 구독 이벤트 수이며 실제 React commit 횟수와 같다는 뜻은 아니다.

### 스냅샷 비용

전체 스냅샷 20회 평균, 현재 격자에 필요한 400행 투영은 100회 평균이다.

| 누적 Q 행 | 전: 전체 복사 ms | 후: 전체 복사 ms | 후: 400행 투영 ms |
|---:|---:|---:|---:|
| 1,000 | 0.115 | 0.145 | 0.046 |
| 10,000 | 0.655 | 0.615 | 0.049 |
| 50,000 | 6.475 | 4.545 | 0.034 |

전체 복사 API의 시간 차이는 JIT/GC 등 실행 변동을 포함한다. 전체 복사를 근본적으로 빠르게 만들었다는 결과로 해석하지 않는다. 핵심 변경은 누적 테이블 크기에 비례하는 전체 복사를 일반 UI 경로에서 없앤 것이다. 처리 범위가 다른 두 API의 비용을 전체 학습 속도 배수로 표현하지 않는다.

### 실제 production UI 30초 실행

20×20 Final Challenge에서 이론 상한 **26,843,545,600**을 가진 맵을 적용한 뒤 데스크톱·모바일 에뮬레이션 각각 6×5초 표본을 수집했다. 중간 Pause/Resume를 포함한 실제 마지막 표본 경과는 약 30.2초다. 기본 자원 예산과 1만 스텝 에피소드 제한을 사용했다.

| 항목 | Desktop | Mobile 에뮬레이션 |
|---|---:|---:|
| 누적 실행 스텝 | 180,800 | 180,800 |
| 생성 Q 행 | 78 | 78 |
| 완료 에피소드(시간 제한 포함) | 22 | 22 |
| Pause / Resume / Stop 확인 ms | 32 / 32 / 60 | 38 / 30 / 38 |
| rAF 간격 평균 / p95 ms | 16.66 / 17.10 | 16.66 / 17.20 |
| 실행 전 GC heap bytes | 4,404,592 | 4,495,432 |
| Stop 후 GC heap bytes | 16,826,896 | 16,893,676 |
| 10회 화면 왕복 후 GC heap bytes | 17,724,648 | 17,862,824 |

조작 확인 시간은 Playwright 통신과 locator 확인 비용을 포함한다. rAF 간격은 React commit 시간의 직접 측정값이 아니다. 이 실행에서 수십억 조합 중 생성한 Q 행은 78개뿐이었다. 모든 가능한 상태를 저장하지 않는다는 실험이지 수렴이나 모든 대형 맵의 성능 보장은 아니다.

이력 보존 때문에 Stop 후에도 heap이 초기값으로 돌아가지 않는다. 화면 왕복 후에도 약 0.9–1.0MB 증가가 관측됐다. 이것만으로 누수 또는 누수 없음으로 판정하지 않는다. 장시간 세션과 더 다양한 경로의 별도 heap 추적이 필요하다. 개발 벤치마크의 browser-specific performance.memory 표본은 보조 정보이며, 위 표와 아래 보존 비용은 CDP JS heap 계측이다. 둘 모두 프로세스 전체 메모리가 아니다.

## 6. 자원 안전장치와 제한

| 기본 정책 | 값 | 의미 |
|---|---:|---|
| 실제 Q 행 예산 | 100,000 | 다음 스텝의 최대 두 lazy 행을 예약할 수 없으면 스텝 전에 일시정지 |
| 저장 스텝 예산 | 500,000 | 완료 이력 + 현재 trajectory가 도달하면 다음 스텝 전에 일시정지 |
| 에피소드 최대 스텝 | 10,000 | MDP 종료와 별도로 truncated 에피소드 기록 후 다음 에피소드 |
| 경고 / 높은 사용량 | 예산의 60% / 85% | 고급 설정에서 경고, 높은 단계에서는 UI 약 4Hz |

GC 측정에서 Q 1만/5만/10만 행의 보존 증가량은 884,312 / 4,143,160 / 8,306,556 bytes였다. 단순 상태 이력 10만 스텝은 7,711,532 bytes였다. 50만 스텝은 이 단순 표본을 선형 환산하면 약 38.6MB이며 직접 측정한 상한이 아니다. 기본 예산은 이 비용 규모와 여유를 고려한 보수적 출발점이다. 긴 키·동적 경로·기기별 JS 엔진은 비용이 달라지므로 메모리 보증값이 아니다.

표시 메모리 추정식은 UTF-16 키 문자 수×2 + 행 수×(행동 수×8 + 오버헤드 허용 96 bytes)다. Q 10만 행 표본의 자체 추정은 15,112,000 bytes로 측정 증가량보다 컸다. 실제 JS 힙이나 프로세스 메모리와 동일하다고 표시하지 않는다.

설정 → 학습 설정 → 고급에서 세 예산을 변경할 수 있다. 일시정지 원인은 항상 보이는 배너로 제공한다. 사용자는 예산을 늘려 재개하거나 현재 에피소드를 중단할 수 있다. 자동으로 Q 행이나 완료 이력을 버리지 않는다. Stop은 기존대로 현재 에피소드만 취소하고 Q-table·완료 이력·환경·하이퍼파라미터를 유지한다. 누적 실행 스텝과 보존 스텝은 구분한다.

시간 제한 전이는 `done:false, truncated:true`다. Q-Learning/SARSA는 미래 Q값으로 bootstrap한 후 환경과 pending action을 새 에피소드로 초기화한다. Goal/Bomb 전이는 기존 `done:true`로 bootstrap하지 않는다. 두 알고리즘 모두 비영 미래 가치에서 시간 제한 목표가 −1.9가 되는 검증과 동일 스텝의 실제 Goal 종료를 별도로 테스트했다.

## 7. 드래그 및 덮어쓰기

선택 도구로 요소를 눌러 **6px** 이상 움직이면 이동 미리보기를 표시하고 Pointer Up에 전체 초안을 한 번 갱신한다. 원본 셀·이동 요소·가능/불가능 도착지를 구분한다. Escape, Pointer Cancel, 격자 밖 놓기는 변경 없이 취소한다. 한 이동은 한 Undo이고, 움직인 셀마다 이력을 추가하지 않는다.

마우스는 선택 도구에서 바로 이동한다. 모바일은 ‘터치 이동’을 켜서 요소를 이동하고, 끄면 확대 격자를 네이티브 스크롤한다. 이 명시적 모드가 터치 패닝과 이동의 충돌을 막는다. 터치 CDP 이벤트와 확대 상태의 마우스 이동을 실제 브라우저에서 확인했다.

벽/Start/Goal/Bomb/포털 끝점/One-way/Fragile/Switch/Toggle Wall을 이동한다. 포털 끝점 하나와 ID, 그룹 ID, 방향을 보존한다. Start는 위치만 바뀐다. 같은 포털의 두 끝점을 한 셀로 합치는 드롭은 차단한다.

배치는 다른 요소를 원자적으로 교체한다. 벽/Bomb/Goal 재클릭은 토글, One-way는 시계 방향 회전, 다른 같은 특수 요소는 중복 없이 유지한다. Start와 마지막 Goal은 덮어쓰기로 사라지지 않는다. 연결 요소를 교체하면 남은 끝점/그룹을 유지하고 오류를 표시하며 적용을 막는다. Undo는 이전 연결과 내용을 한 번에 복원한다. 기존 비전체 화면 레거시 편집 API는 호환성을 위해 기존 배치 의미를 유지하고, 실제 앱의 전체 화면 편집기에 새 정책을 적용했다.

## 8. 포털 및 그룹 자동 연결

기본 자동 모드는 초안에서 불완전 쌍/그룹을 우선 완성하고, 없으면 충돌하지 않는 최소 P숫자/G숫자를 찾는다. P1 두 끝점 완료 후 P2로, 스위치·벽을 갖춘 G1 완료 후 G2로 진행한다. 벽부터 놓는 순서도 지원한다.

현재 ID는 툴바에 표시한다. 속성의 기존 ID 목록·직접 입력·자동 체크박스로 수동 제어하며, 그룹의 ‘현재 그룹에 계속 추가’로 여러 스위치/벽을 연결한다. 목록은 끝점 수와 S/W 개수를 표시한다. 수동 ID 입력은 자동 선택을 끈다. ID 선택은 현재 초안으로부터 계산하므로 Undo/Redo 후 불완전 연결/사용 가능한 다음 ID도 복구된다. UI 선택만으로 이력을 만들지 않고 실제 ID/좌표 변경은 전체 초안 이력에 포함한다.

## 9. 아이콘

가벼운 공통 `EditorIcon` SVG를 사용한다. 같은 24×24 좌표계·1.7px 획·평면 실루엣으로 커서, 벽돌, 에이전트 시작 마커, 깃발, 폭탄, 이중 고리, 화살표 타일, 금 간 바닥, 누름 버튼, 문, 지우개, 곡선 Undo/Redo를 제공한다. 색 외에 형태·aria-label·기존 설명형 Tooltip·선택 강조를 유지한다. 새 아이콘 의존성은 없다.

## 10. 가이드 스크롤

`.guide-page`가 유일한 본문 세로 스크롤 컨테이너다. 소개 제목도 그 안에 있으며 아래로 읽으면 사라진다. 42px로 줄인 상단 breadcrumb와 작은 sticky 단원 목차만 남는다. `.guide-content`의 독립 overflow는 제거했다. 하단 160px 읽기 여백으로 언어 선택기와 마지막 콘텐츠를 분리했다. 기존 6단원과 계산기 값 변경, 한국어/영어, 메인 사이드바 고정을 유지한다.

## 11. 홈 레이아웃

소개와 데모 카드의 상단 기준선을 맞추고 상단/히어로 여백을 줄였다. 제목·설명·CTA를 왼쪽에, 환경 이름·선택·실제 격자를 오른쪽에 둔다. 아래의 큰 설명 카드/중복 알고리즘 소개 대신 학습 환경·편집기·가이드로 이동하는 작은 링크 3개를 제공한다. 모바일은 자연스러운 한 열이다.

## 12. 다중 환경 시연

기본 탐색, Portal, Switch/Gate, Fragile, One-way의 5개 시나리오다. 각 모드의 행동 스크립트를 별도 GridWorldEnv에 재생해 프레임을 만들며 실제 학습 엔진과 연결하지 않는다. ‘설명용 시연/실제 학습 결과 아님’을 표시한다. 기본 탐색/활용 경로 비교를 유지한다.

자동 재생, 끝점 잠시 표시 후 다음 시나리오, 직접 선택, 일시정지/재개/한 걸음/초기화, reduced-motion, document/viewport 밖 타이머 정리를 제공한다. 일반 이동은 부드럽게, 포털은 벽을 가로질러 미끄러지지 않도록 즉시 이동한다. 스위치의 실제 열린 상태, 붕괴 후 재진입 차단과 One-way 금지 방향의 제자리 페널티를 실제 모델로 표시한다. 모든 시나리오의 양쪽 모드가 실제 Goal 완료로 끝나는지 테스트했다.

## 13. 신규 프리셋과 해결 검증

기존 16개를 보존한 **총 25개**다. 갤러리에 검색, 크기/난이도/환경 요소/유형 필터를 추가하고 기존 오른쪽 패널·큰 미리보기·명시적 학습 적용/초안 불러오기를 유지한다.

| 신규 맵 | 크기 | 학습 목표 | 검증 행동 수 |
|---|---|---|---:|
| Spiral Maze | 12×12 | 나선형 긴 경로의 지연 보상 | 83 |
| Portal Network | 15×15 | 세 포털 쌍과 분리된 영역 | 5 |
| One-way City | 16×16 | 도시 블록의 출발 방향 제약 | 27 |
| Switch Factory | 14×14 | 독립적인 세 그룹 문을 순차 개방 | 13 |
| Collapsing Ruins | 15×15 | 30개 붕괴 바닥과 되돌릴 수 없는 경로 | 56 |
| Multi-goal Expedition | 20×20 | 네 Goal 순서와 포털 지름길 | 77 |
| Risky Shortcut | 20×16 | Bomb 옆 짧은 길과 북쪽 안전 우회 | 27 |
| Giant Mixed Maze | 20×20 | 옆방 Goal을 먼저 수집하고 다리에 진입 | 40 |
| Final Challenge | 20×20 | 3 Goal·2 포털 쌍·3 그룹·20 Fragile | 44 |

각 `solution`을 실제 GridWorldEnv로 재생하여 마지막 행동에만 정상 완료되고 모든 Goal이 사라지는지 확인한다. 신규 맵은 무제한 BFS를 하지 않는다. 기존 동적 프리셋의 BFS는 유지했고, 탐색 예산 초과는 ‘해결 불가능’ 대신 solvability unknown 오류로 구분했다. 해결 경로 존재와 학습 수렴은 다르며 큰 맵의 250 에피소드 수렴을 보장하지 않는다.

30×30은 이번에 확대하지 않았다. 실제 레이아웃·터치·렌더 검증 범위를 기존 20×20까지로 유지했고, 900셀의 모바일 편집/포커스/렌더를 같은 수준으로 검증하지 않았다. 단순 크기 확대를 검증 없이 안전하다고 선언하지 않는다. 20×20에서도 이론 상태 공간이 큰 맵을 적용하는 핵심 문제는 해결했다.

## 16. 알려진 한계

- 검증은 수십 초 반복과 각 30초 production UI 실행이다. 수시간 안정성·누수 없음·모든 맵의 수렴을 주장하지 않는다.
- 실제 Q/이력 예산은 조정 가능한 soft guard이며 정확한 프로세스 메모리 상한이 아니다. 긴 상태 키, 여러 브라우저 탭, 큰 사용자 예산에서 추가 비용이 발생한다.
- 명시적 전체 스냅샷/전체 구독은 여전히 전체 테이블 비용을 낸다. 일반 UI가 이 경로를 사용하지 않는 것을 테스트했다.
- 8ms는 스텝 사이 yield 목표다. 단일 스텝, GC, 외부 전체 구독자나 브라우저 렌더를 선점할 수 없다.
- 높은 상태 조합 자체는 실행 가능하지만 표본에서 방문한 상태는 적었다. 수십억 상태를 실제로 탐색하거나 저장하는 성능 검증이 아니다.
- 모바일은 Edge 터치 에뮬레이션/CDP 검증이며 물리 iOS/Safari/Android 기기는 검증하지 않았다. 30×30도 검증 범위에 포함하지 않았다.
- 임의 편집 맵의 해결 가능성은 적용 조건이 아니다. 불가역 지형으로 막힐 수 있으며 시간 제한/중단/맵 수정이 필요할 수 있다.
- Undo/Redo는 현재 세션의 초안이다. 적용 이전의 실험 데이터나 새로고침 후 전체 세션 복구 기능은 추가하지 않았다.
