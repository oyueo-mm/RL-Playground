# 고속 학습 및 학습·카메라·보상 UX 개선

작업일: 2026-10-26 (Asia/Seoul). 브랜치: `feat/home-redesign`.

## 1. 기준과 범위

작업 전 로컬과 fetch 후 원격 HEAD는 모두 `32b7a0e1df26f500843055157a4225911f2d2013`이며 작업 트리는 깨끗했다. 실제 엔진·Scheduler·React 구독·카메라·프리셋 적용 진입점·기존 테스트와 벤치마크를 확인했다. 기존 시스템을 재작성하지 않았다. `main` 병합이나 Production/Pages 배포는 하지 않는다.

기존 30개 공식 맵, V2 12개, 11번 수정 맵, 성공 경로, PNG, catalog 및 manifest는 변경하지 않았다. V2 보고서·감사 자료와 과거 벤치마크/스크린샷을 보존한다. 새 검증 자료에는 `turbo-` 접두사를 사용한다.

## 2. 따라가기 카메라

줌 비율과 따라가기 상태를 독립적으로 유지한다. `followAgent()`가 에이전트·맵 크기·실제 viewport 셀 크기·줌에서 카메라 오프셋을 계산한다. follow ON의 화면 위치는 `(agent + .5 - map/2) × cellScale × zoom + cameraOffset = 0`이다. 위치를 effect로 다시 설정하는 피드백 루프를 제거했다.

휠 줌·+/−·핀치 시 follow를 끄지 않는다. follow ON이면 커서/핀치 중심의 이동보다 에이전트 중심을 우선한다. 두 손가락 제스처는 확대 비율만 반영하고 추적 중심은 유지한다. follow OFF에서는 기존 커서/핀치 중심 줌과 두 손가락 평행 이동을 유지한다. 한 손가락/마우스 드래그와 트랙패드 패닝은 명시적 패닝이므로 follow를 해제한다. viewport/분석 패널 크기 변경은 줌을 초기화하지 않고 추적 중심을 다시 계산한다. 새 환경 적용과 Fit은 명시적으로 맞춤 상태로 돌아간다.

64×64에서 실제 agent-marker의 화면상 중심과 viewport 중심의 거리를 2px 미만으로 검증했다. 단순 상태 플래그만 검사하지 않았다. 모바일 CDP 핀치 확대/축소, 휠, 버튼, 이동 중 추적, 분석 패널 크기 변경, 수동 패닝을 검사한다. 모바일 wheel delta가 emulation 배율의 영향을 받으므로 특정 입력 delta의 배수 대신 실제 줌 증가와 중심 위치를 검사한다.

## 3. 보상 기본값과 배치

기본값은 맵 보상 ON, 실시간 HUD OFF, 애니메이션 ON이다. 사용자 설정은 화면 이동, 학습 시작/중단, 모드 변경으로 덮어쓰지 않는다.

긴 규칙 문구는 맵 보상 토글과 분리했다. 시각화 설정의 `ⓘ` 버튼으로만 규칙 카드를 연다. Goal/Bomb/이동/이동 실패의 실제 설정값과 최초 Goal 수집 규칙을 한영으로 설명한다. 닫기 버튼, Escape, 외부 클릭으로 닫으며 기본적으로 닫혀 있다. 외부 클릭은 대상 체크박스의 클릭 이후에 처리해 설명 카드가 접힐 때 입력이 누락되지 않게 했다.

맵 아래 `camera-chrome` Flex 영역에 미니맵·선택적 HUD·줌/따라가기 버튼을 배치했다. 화면을 가리는 z-index 경쟁 대신 실제 레이아웃 공간을 예약한다. 모바일은 HUD/미니맵 행과 조작 버튼 행을 나눈다. HUD는 두 수치 중심의 작은 영역이며 모바일에서 지난 에피소드의 보조 문구를 숨긴다. 적용/자원 알림도 맵 위의 독립 레이아웃 행에 둔다. 설정이 열리면 알림은 숨기고 설정 팝오버는 카메라 조작 영역 위에서 스크롤한다. 이동한 알림의 기존 백분율 높이 제한이 텍스트를 자르는 문제도 이미지 QA 후 수정했다.

Goal 최초 수집·Bomb 진입·step/wall 보상 규칙은 바꾸지 않았다. 셀 화면 너비 28px 미만에서 맵 숫자를 숨기는 제한과 대표 전이 하나의 650ms 애니메이션을 유지한다. 고속 모드에서는 보상 컴포넌트와 타이머를 아예 마운트하지 않는다.

## 4. 난이도별 에피소드 수

단일 순수 함수 `defaultEpisodesForDifficulty()`가 공식 내부 ID를 사용한다. 맵 크기로 난이도를 추정하지 않는다.

| ID | 난이도 | 기본 에피소드 |
| --- | --- | ---: |
| very-easy | 매우 쉬움 | 100 |
| easy | 쉬움 | 250 |
| medium | 보통 | 500 |
| hard | 어려움 | 1,000 |
| very-hard | 매우 어려움 | 2,000 |

갤러리 적용과 홈 시연의 실험 시작 모두 확인 후에만 해당 기본값을 적용한다. 선택·미리보기·적용 취소·편집 초안 불러오기는 값을 바꾸지 않는다. 이후 사용자가 바꾼 값은 페이지 이동, Pause/Resume, 결과 실행에서도 유지한다. 다음 공식 프리셋을 적용하면 새 난이도의 값을 사용한다. 사용자 제작 환경은 현재 입력을 보존하며 최초 기본값은 250이다. 입력과 엔진 API 모두 양의 안전한 정수만 허용한다. 권장값은 학습 수렴 보장이 아니라는 짧은 안내를 표시한다.

## 5. 일반/고속 학습 UI

기본 선택은 일반 학습이다. 상단 모드 선택과 기존 학습하기 버튼 하나를 사용한다. 실행·일시정지 중 모드 변경을 막고 중단/완료 후 변경할 수 있다. 기존 일반 속도 슬라이더 값은 보존하며 고속 실행 중 비활성화한다.

고속 실행 중 지도와 Policy/Value/Trajectory/보상 애니메이션 컴포넌트를 언마운트하고 진행 대시보드를 표시한다. 단순히 display:none을 설정하지 않았다. 편집기·분석은 기존 DeferredPanel 경계를 유지하고 고속 실행 중 분석 패널을 열지 않는다.

대시보드는 완료/목표 에피소드, 완료 기준 진행률, 실제 평균 steps/s와 episodes/s, 이번 실행 성공 횟수/성공률, 최근 평균 보상/성공률, 스텝 수, 실제 학습 시간을 표시한다. 최근 통계는 이번 실행에서 완료된 최근 최대 100개 에피소드이고, 처리량과 성공 합계는 이번 실행 전체다. 일시정지 시간은 경과 시간에서 제외한다. 중단·완료 요약은 고정해 이후 단일 step API가 그 수치를 바꾸지 않게 했다.

## 6. 선택한 실행 구조와 Worker 검토

동일 `SimulationEngine`·Environment·Agent·Q-table을 유지하는 cooperative main-thread 배치 방식을 선택했다. Worker와 Q-table을 왕복 복제하지 않는다. 이로써 SARSA pendingAction, 난수 순서, 에피소드 중간 상태, 기존 기록 보관 정책을 그대로 이어간다.

Scheduler에 일반 speed와 독립된 turbo 실행 전략을 추가했다. 약 8ms의 짧은 계산 청크 뒤 setTimeout(0)으로 이벤트 루프에 양보한다. 32개 행동마다 시간 예산을 검사하고, 각 행동 사이에는 세대 토큰을 검사한다. 정지된 테스트 시계에서도 청크당 최대 50,000회로 유한하다. 일반 interval/batch 방식과 기존 8ms 제한은 보존한다. 사용자 일반 속도는 turbo 시작/종료로 덮어쓰지 않는다.

고속 UI 발행 주기는 750ms다. 상태 변경(Start/Pause/Resume/Stop/Reset/완료/자원 한도)은 즉시 발행한다. 활성 고속 UI snapshot은 시작 전의 고정 시각화 참조를 재사용하고 새로운 맵 모델·visible Q 키·전체 Q-table 투영·이력 복사를 생성하지 않는다. React는 새로운 작은 통계와 `turbo` 요약을 사용한다. 완전한 진단 `getSnapshot()`은 명시적으로 요청할 때만 비용을 지불한다. 진단 subscriber만 있을 때도 주기 발행을 제한한다. 종료 후에는 현재 맵/Q 투영을 한 번 갱신해 일반 화면과 결과 실행에 연결한다.

Worker는 별도 학습 알고리즘으로 분기하지 않아야 하고, 최대 100,000 Q행과 동적 상태/기록의 복제·전송·소유권 관리가 추가된다. 이번 측정에서는 이 복잡도 없이도 큰 처리량 증가와 53–79ms의 Playwright Pause 처리, 약 23–24ms의 프레임 간격 p95를 얻었다. 따라서 이번에는 도입하지 않았다. **Worker prototype과의 직접 벤치마크는 수행하지 않았으므로 Worker보다 빠르다고 주장하지 않는다.** 다기기·다중 코어 사용이 필요하면 후속 검토할 수 있다.

## 7. 알고리즘과 Q-table 동등성

전이, epsilon-greedy 선택, TD 계산/업데이트, Goal bitmask, Terminal/Truncated 처리는 같은 `performOneStep()`을 사용한다. 고속 모드도 모든 학습 업데이트와 통계/경로 누적을 수행한다. `policy-loop`/`trapped` 조기 종료는 재도입하지 않았다.

고정 난수 시드에서 Q-Learning/SARSA 각각 일반 60개 에피소드, 고속 60개 에피소드, 일반→고속→일반 각 20개 연속 학습을 비교했다. Q-table·상태·마지막 전이·TD·전체 보관 통계·총 스텝이 일치한다. 별도로 실제 Goal/Bomb 종료 보상, max steps truncated, Q 예산 도달, 부분 경로 보관을 검증했다. 시간 제한 표본은 고속이 더 많은 업데이트를 수행하므로 5초 후 Q-table이 같은지 비교하지 않고, 동일 학습량 테스트로 동등성을 검증한다.

## 8. 제어·수명·자원 안전성

Pause는 청크를 취소하고 누적 학습 시간을 고정한다. Resume은 동일 pendingAction·Agent·통계를 이어간다. Stop은 현재 에피소드만 취소하고 완료 이력/Q-table을 보존한다. Reset은 명시적인 확인 후 기존 의미대로 학습을 초기화한다. 초기 요약을 받는 subscriber가 즉시 Pause/Reset해도 뒤늦은 Scheduler가 실행되지 않도록 재진입 상태를 확인한다.

실행 중 mode 변경과 중복 run을 막는다. paused run은 Resume으로만 재개한다. 고속 상태에서 다른 화면으로 이동하거나 Simulator가 언마운트되면 일시정지한다. 결과 화면에도 진행 상태를 표시하며 `학습 중단 후 분석 보기`로 Q-table을 보존한 채 최신 분석으로 전환할 수 있다. Worker가 없으므로 중복 Worker나 분리된 Q 소유자가 생기지 않는다.

기존 기본 자원 한도(Q 100,000행, 상세 전이 500,000개, 상세 에피소드 100개, episode max steps 10,000)를 유지한다. 요약 이력은 최근 최대 10,000개이며 lifetime 통계는 계속 보존한다. 자원 한도 변경으로 Q행을 임의 삭제하지 않는다. Q 예산은 한 행동에서 생성 가능한 행을 미리 예약해 초과를 막고 Pause한다. 기록은 기존 FIFO 보관 정책을 따른다.

## 9. 고속 학습 후 결과 실행

결과 실행은 고속 상태를 해제하고 정상 맵을 표시한다. `sliderToSpeed(45)` Normal에서 시작하며 실행/일시정지 중 속도를 조절할 수 있고, 종료/중단/Reset 후 원래 일반 속도를 복원한다. Q-table을 변경하지 않고 greedy policy만 관찰한다. 최대 스텝 제한을 지킨다. 고속 중 렌더링을 생략할 뿐 시각화 옵션 값을 OFF로 바꾸지 않으므로 이전 옵션이 그대로 돌아온다.

| 보상 애니메이션 노드 최대 | 1 | 1 | 0 |

고속은 CPU를 더 적극적으로 사용하며 같은 시간에 훨씬 많은 학습을 한다. Q행이 더 많은데도 표본 보관 메모리는 예산 내에 있었다. 각 표본의 상세 기록 수·Q행·추정 Q bytes·heap 전후·episodes/s·ScriptDuration·Pause 상태를 JSON에 기록했다. CPU 수치는 OS 전체 프로세스 사용률이 아니라 CDP 메인 렌더러 지표이며 표본 종료 시 Pause/GC 계측 비용도 포함한다. Pause 시간은 Playwright의 입력 준비/프로토콜 비용을 포함해 순수 엔진 pause 함수 시간과 구분한다.

개별 청크는 짧지만 메인 스레드에서 실행하므로 Worker와 같은 병렬 실행을 제공하지 않는다. 브라우저 백그라운드 탭 타이머 제한에 따라 처리량이 낮아질 수 있다. 5초 두 표본과 기존 long-run 회귀로 무제한 장기 메모리 안정성을 증명하지 않는다.

## 14. 남은 제한과 후속 권고

- Worker 미도입: 주 스레드의 짧은 청크 방식이다. 8ms는 32행동마다 확인하므로 한 행동 비용/브라우저 지연 때문에 엄밀한 hard deadline은 아니다.
- 활성 고속 UI snapshot의 visual 필드는 고정 참조다. 분석은 고속 실행 중 비활성화하며 최신 시각화는 종료 시 복원한다. 진단이 필요하면 명시적인 full snapshot을 요청한다.
- 모드 전환 때 맵 뷰를 언마운트하므로 고속 이후 카메라는 맞춤 상태로 다시 마운트한다. 시각화 체크박스와 일반 속도·에피소드 입력은 보존한다.
- 일반 학습의 큰 SVG와 기존 500kB chunk 경고는 남는다. 최종 JS는 638.26kB / gzip 151.53kB, CSS는 67.00kB / gzip 15.09kB이며 전체 결과는 build 로그에 기록한다.
- 고속 모드가 복잡한 V2의 수렴이나 목표 성공을 보장하지 않는다. 전체 동적 안전성이 미완료인 큰 프리셋의 이전 감사 제한도 그대로다.
- 더 긴/여러 기기 표본, CPU power 사용량, 필요 시 Worker 소유권/전송 비용을 비교하는 후속 연구가 가능하다.
