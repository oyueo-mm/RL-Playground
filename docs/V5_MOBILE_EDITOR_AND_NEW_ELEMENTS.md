### 구성과 동작
- **도구 막대** (`src/ui/ToolStrip.tsx`, `mobileTools.ts`): 선택·벽·목표·폭탄·지우개를 맨 앞에, 시작·포털·단방향·붕괴·스위치·토글 벽·늪을 그 뒤에. `role="toolbar"`, 각 버튼 `aria-pressed`, 설명은 `title`(터치에는 hover가 없으므로 툴팁 대신). 아직 스크롤할 도구가 있는 쪽에만 페이드와 `›` / `‹`가 나타나는 **스크롤 힌트**. 활성 도구는 자동으로 보이는 위치로 스크롤된다.
- **한 손가락 동작**: 그리기/이동/지우기(편집) 또는 화면 이동. 화면 이동에서는 한 손가락 드래그가 카메라만 움직이고 아무것도 배치하지 않는다(E2E로 확인). 움직임 없는 탭은 기존 클릭 경로를 그대로 지나가므로 한 칸 배치/선택이 일어나는 것이 의도이지만, 이 경로는 별도 테스트로 고정하지 않았다. 두 손가락 핀치·이동은 항상 카메라. 기존 `GridViewport`에 `touchPan` 속성만 추가했고 카메라·편집 엔진은 재작성하지 않았다.
- **격자**: 기존 `GridViewport`의 Fit/줌/이동을 그대로 사용. 확대·축소 컨트롤은 작게 해서 격자 오른쪽 위 모서리에 겹쳐 놓았다. 레이아웃은 `100%`/`flex`/`min-height: 0` 체인이라 `100dvh` 변화에 따라 재계산되고, 액션 바는 `env(safe-area-inset-bottom)`을 반영한다.
- **속성 시트**: 선택 모드에서 요소를 누르면 열리며 **격자 위에 덮이지 않고 격자 아래 공간을 차지**한다(처음에는 선택한 칸을 시트가 가렸다. 스크린샷에서 발견해 흐름 안 배치로 바꿨다 — 격자가 시트 위 영역에 다시 맞춰져 선택한 칸이 항상 보인다). 기본(peek) 높이는 화면의 약 40%, 핸들로 펼치면 72%. 긴 그룹 목록은 시트 안에서 스크롤. 입력 필드를 누르면 시트 안에서 보이는 위치로 스크롤된다. 닫기: ×, Esc, `속성` 버튼. 바깥(격자) 탭은 다른 요소 선택에 쓰이므로 닫기 동작으로 쓰지 않았다.
- **키보드**: `visualViewport`로 화면 키보드가 가린 높이(`--kb`)를 계산해 편집기 높이를 줄여 시트와 액션 바가 키보드 위에 남게 한다. 순수 함수(`keyboardInset`)는 단위 테스트했지만 **실제 소프트 키보드는 이 환경에서 띄우지 못했다**(§9).
- 기존 기능 유지: 드래그 연속 배치(보간, 스트로크당 Undo 1회), Redo, 드래그 취소(포인터 취소·Esc·핀치), 요소 이동 드래그, 키보드 조작, 직접 플레이, 적용.

## 2. 늪(험지)

**규칙**: 통과 가능한 정적 타일. **진입하는 이동**의 보상이 `stepReward` 대신 늪 비용이 된다.
- 비용 = 타일의 `cost`, 없으면 맵의 `terrainCost`, 그것도 없으면 `-1`.
- 비용은 **유한한 실수이며 0 이하**: `0`과 음수 허용, 양수·NaN·±Infinity·문자열은 오류(양수는 반복 보상 루프를 만들 수 있어 이번 범위에서 제외).
- 벽·경계·닫힌 문에 막힌 이동은 늪 비용이 아니라 기존 `wallPenalty`. 목표/폭탄/포털과 같은 칸에는 둘 수 없다(기존 비중첩 규칙, `Overlapping map elements`).
- 같은 늪에 다시 들어가면 **매번** 같은 비용. 늪 비용은 일반 칸에서는 `stepReward`로 돌아간다.
- **상태 공간**: 정적이므로 상태 키·비트·`stateSpaceEstimate`가 변하지 않는다(테스트로 단언).

구현: `GridWorldEnv.indexConfig()`가 셀별 비용 `Map`을 만들고 `step()`의 일반 이동 분기에서 `terrainCosts.get(key) ?? stepReward` 한 번 조회.

**편집기**: `늪` 도구(데스크톱·모바일), 탭 배치, 드래그 연속 배치, 다시 탭/지우개 삭제, Undo/Redo, 선택 도구 속성(**맵 기본값 사용 / 개별 값 지정**), 맵 속성의 **늪 기본 비용**. 타일에는 물결 무늬와 비용 숫자(`−1`, `−4`)가 표시된다. 지형 색(청록 회색 `#d3e6e8`, 물결 `#3a7f89`)은 일반 바닥·단방향 타일(연한 파랑)과 UI 파랑과 모두 구별된다. 접근성: 셀 레이블 `Swamp, cost -4`.

## 3. 단방향 포털

**규칙**: 기존 쌍에 `directed: true`를 더하면 `ends[0]`(입구 A) → `ends[1]`(출구 B)만 이동한다. B로 일반 이동해 들어가도 A로 돌아가지 않으며(B는 보통 칸) 한 행동에서 포털은 한 번만 발동한다. `directed`가 없으면 기존 양방향 그대로. 상태 비트 추가 없음. 두 끝점이 없는 쌍은 기존처럼 적용 거부.

**편집기**:
- 포털 도구의 **"단방향 포털로 배치"**(첫 칸 A → 둘째 칸 B).
- 선택 도구 속성: **양방향 / 단방향** 전환, **입구 A / 출구 B** 좌표, **방향 뒤집기 (A ↔ B)**, 포털 ID, 연결 상태와 오류 문장.
- **끝점을 다른 칸으로 옮겨도** A/B 슬롯·`directed`·연결이 유지된다(예전 코드는 지웠다가 뒤에 추가해서 순서가 뒤바뀔 수 있었다 → 끝점을 제자리 교체하도록 수정, 테스트로 고정).
- 표시: 입구 `◎ P1→`, 출구 `◉ →P1`(색이 아니라 글자·기호로 구별), 선택하면 점선 연결선 끝에 **화살촉**. 모바일에서도 같은 표시.
- 알려진 한계: 한쪽 끝점을 **삭제**한 뒤 같은 ID로 다시 놓으면 새 끝점이 B가 된다(남은 끝이 A로 취급됨). 쌍이 미완성이라 적용이 막히고 오류 문장이 안내하며, 필요하면 `방향 뒤집기`로 바로잡는다.

## 4. 데이터 스키마와 기존 파일 호환성

```ts
interface TerrainTile extends Position { cost?: number }
interface PortalPair { id: string; ends: Position[]; directed?: true }
GridFeatures { terrains?: TerrainTile[]; terrainCost?: number }   // terrainCost는 terrains가 있을 때만 의미
```
- **내보내기**: 늪 또는 단방향 포털이 있는 맵만 **버전 4**. 이전 기능만 쓰면 이전과 똑같이 v2(또는 개별 보상·초기 문 상태가 있으면 v3). `terrains`가 없으면 `terrainCost`도 내보내지 않는다.
- **가져오기**: v1·v2·v3·v4 모두 정상. v1~v3 파일에 새 필드가 들어 있으면 **조용히 버리지 않고** `늪과 단방향 포털은 JSON 버전 4가 필요합니다.` 오류. 잘못된 비용(`> 0`, NaN, 문자열), 좌표 밖·겹침, 미완성 포털 쌍, 잘못된 `directed` 값(`false`·문자열)도 각각 오류 문장.
- JSON 왕복에서 비용·방향·끝점 순서가 정확히 유지된다(`parseEnvImport(serialize(x)) == x`, 재직렬화 바이트 동일).
- **공식 프리셋 30개의 원본 파일은 수정하지 않았다.** 30개 모두 이전과 같이 v2로 내보내지고 새 필드가 나타나지 않음을 테스트가 단언한다(기존 테스트).

## 5. 상태 공간 영향

없음. 늪은 정적 비용, 단방향 포털은 정적 연결이라 상태 키(`x,y,목표마스크[,붕괴마스크,토글마스크]`)와 이론 상태 수 상한이 변하지 않는다. 새 맵과 늪·포털 제거 맵의 `stateSpaceEstimate`·`stateSpaceDetails().text`·첫 상태 키 일치를 테스트했다. 늪/단방향 포털이 상태 키를 합치거나 새로 나누지 않으므로 Q-Learning/SARSA 수식은 건드리지 않았다.

**기존 테스트 수정**(검증 약화 없음): ① 도구 수 단언 11 → 12(늪 추가), ② `touch-move-mode`/`touch-paint-mode` 토글이 하나의 명시적 모드(`touch-edit-mode`/`touch-pan-mode`)로 바뀌어 같은 동작(배치 vs 이동)을 새 컨트롤로 단언, ③ 호버 툴팁 단언은 터치 도구 줄에서는 `title` 단언으로, ④ `expectFits`는 플로팅 툴바 대신 phone의 상태 줄·액션 바를 기준으로 격자 위치를 단언.

## 7. 공식 프리셋 회귀

30개 프리셋 성공 경로를 실제 `GridWorldEnv.step()`으로 재생(`validateSolutions.test.ts`)해 모든 목표 순서·이벤트·종료·목표 보상이 일치하고, V3 25~30번 경로 길이 **211 / 234 / 190 / 202 / 324 / 419**와 종료 조건이 유지됨(`scripts/v3Presets.test.ts`). 맵·해 파일 해시도 그대로. 프리셋 JSON에는 새 필드가 없어 늪/방향 로직을 지나지 않는다. 시드 고정 장기 실행 9개 프리셋에서 V5와 `main`의 총 스텝·에피소드·탐험/활용·종료 사유·Q 행 수가 **9/9 동일**.

## 8. 성능

`npm run benchmark`(Edge headless, 1366×768)를 V5와 `main`(`aad2d34`)에서 순차 실행. 원시 결과: `benchmarks/results/v5*.json`, `v5-baseline-aad2d34*.json`.
- 엔진 장기 실행(동기 500,100스텝): 가장 큰 프리셋(23번) 448,074 vs 463,748 steps/s(−3%, 측정 잡음 범위), 나머지 프리셋은 이 벤치의 시간 해상도로는 계산되지 않아 비교하지 않음. 궤적은 9/9 동일.
- 대형 맵 SVG 렌더(정책·가치 오버레이): 20×20 44/52 ms, 32×20 30/30, 48×40 63/60, 64×64 221/79 (V5/main). 64×64는 단발 편차가 크다(교대 3회: V5 75·155·155, main 79·82·246) → **회귀 없음**으로만 판단. 100k 전이 96~129 vs 95~139 ms, 프레임 p95 41~50 vs 40~60 ms.
- 새 SVG 요소는 늪·포털 타일뿐이라 늪이 없는 맵의 렌더 비용은 늘지 않는다.

## 9. 남은 제한

- **실기기 터치는 확인하지 못했다.** 모바일 검증은 Edge의 iPhone 13 프로필과 CDP 실제 터치 이벤트이며, 실제 iOS Safari/Android Chrome은 아니다. 특히 **소프트 키보드**(`visualViewport`)와 iOS의 세로 스크롤 거동은 이 환경에서 재현할 수 없어 로직(순수 함수·단위 테스트)과 시트 내 스크롤 위치까지만 검증했다.
- 768×1024 태블릿은 데스크톱 편집기 레이아웃이다(모바일 레이아웃은 ≤760px).
- 시트의 "바깥 탭으로 닫기"는 구현하지 않았다(격자 탭이 다른 요소 선택이기 때문). 닫기는 ×, Esc, `속성` 버튼.
- 단방향 포털 끝점 삭제 후 재배치 시 슬롯 규칙은 §3의 한계 참조.
- 늪 비용은 0 이하만 허용한다. 양수 비용·보상 타일은 의도적으로 제외했다.
- 모바일 도구 막대의 도구 설명은 `title`(길게 누름/보조기기)이며 별도의 터치 툴팁은 없다.
- 이 문서의 벤치 수치는 단발 측정이 섞여 있어 작은 차이에는 의미가 없다.
