## 6. 결과 실행 속도

시작 직전 Scheduler 속도를 `savedTrainingSpeed`로 보존하고 `sliderToSpeed(45)`로 시작한다(113ms/step, Normal 구간). 실행·일시정지 중 슬라이더는 활성 상태이고 `setSpeed`는 현재 Scheduler만 변경한다. 저장한 일반 학습 속도는 덮어쓰지 않는다. UI는 엔진의 현재 속도를 읽고 변경 시 snapshot을 발행한다. 종료·중단·초기화 때 원래 속도를 복원한다.

Scheduler의 세대 토큰 및 취소·재예약 동작을 유지해 속도 변경 자체가 추가 행동을 실행하지 않는다. greedy 실행은 epsilon 설정을 변경하지 않고 Q-table 읽기만 하며 TD 업데이트·새 Q행 생성을 수행하지 않는다. Q-Learning/SARSA, 일시정지·재개, 최대 스텝 종료, 성공 종료, Stop 및 Reset의 속도 복원과 Q-table 불변을 테스트했다.

## 7. 프리셋 적용과 편집 분리

어느 화면에서나 `맵 적용하기` → 확인 → 한 번의 `engine.reset` → 갤러리 닫기 → 학습 환경 이동 → 카메라 맞춤 → 성공 메시지 순서다. 취소하면 환경·학습 데이터·기존 화면을 유지하며 갤러리도 유지한다. 미리보기는 엔진을 변경하지 않는다. 홈에서 갤러리를 여는 것만으로 화면을 학습 화면으로 바꾸지 않는다.

별도 `편집기로 불러오기`는 초안만 로드하고 편집 화면으로 이동한다. 학습 환경은 그대로이고 기존 Undo/Redo 정책을 사용한다. 홈 시연에서 실험 시작도 확인 후 적용·이동·카메라 맞춤·성공 알림을 제공한다. 홈/학습/편집 진입별 취소·정상 적용·단일 reset·편집 전용 동작을 자동 검증했다.

## 8. 보상 시각화

- 맵 보상: 남은 Goal의 최초 수집 보상과 Bomb 진입 페널티를 표시한다. 수집 Goal은 맵 숫자에서 제외한다. 범례에 Goal/Bomb/일반 이동/이동 실패 보상과 최초 수집 규칙을 표시한다. 벽 칸에 진입 보상을 적지 않는다. 셀 화면 너비가 28px 이상일 때만 숫자를 표시한다.
- 실시간 보상: `lastTransition.reward`와 `stats.episodeReward`를 사용한다. 종료 직후에는 완료 보상을 유지하고 마지막 완료 에피소드도 따로 표시한다. 새 행동/Reset에 맞춰 표시를 갱신한다.
- 애니메이션: 대표 전이 하나의 SVG 숫자가 650ms 동안 나타난다. 양·음수는 부호와 색으로 구분한다. 기존 80ms UI 발행 주기에만 반응하며 엔진 매 스텝 DOM을 만들지 않는다. reduced-motion을 존중한다.

한영 옵션·모바일 레이아웃·학습 및 결과 실행을 지원한다. Q값과 실제 보상을 설명으로 구분한다. 기존 Policy/Value/Trajectory overlay 및 카메라 조작은 유지한다. 적용 알림과 보상 영역을 분리하고 설정 패널을 열 때 알림을 숨겨 클릭 방해를 방지했다.

## 9. 자동 조기 종료 제거와 유지 조건

`policyStates`, `policyLoopDetected`, `blockedSteps`, `trapped`/`policy-loop` 런타임 종료 분류 및 관련 UI·통계 항목을 제거했다. 동일 전체 상태 재방문과 16회 이상 이동 실패가 종료를 유발하지 않는다. 실패 보상과 정상 TD 업데이트는 유지한다.

성공·Bomb/실제 환경 종료·`maxEpisodeSteps`에 의한 truncated·수동 Stop·Reset·자원 한도 일시정지는 유지한다. 일반 학습과 greedy 결과 실행 모두 최대 스텝을 적용하므로 반복 정책도 무제한 실행되지 않는다. 오프라인 안전성 감사와 과거 실험 문서는 별개로 보존한다.

## 11. 성능 측정

같은 기기·Edge headless 1366×768·실제 React 학습 화면·같은 seed12345·α=.1/γ=.9/ε=.3·batch100·기본 자원 예산으로 각 조건을 5초씩 2회 측정했다. 2회차는 조건 순서를 뒤집었다. 비교 실행 동안 다른 테스트 스위트는 실행하지 않았다. Policy/Value/Trajectory는 켜고 보상 옵션 세 개만 모두 끄거나 켰다. [재현 스크립트](../scripts/compare-v2.mjs), [원시 결과](../benchmarks/results/v2-paired-ui.json).

모든 표본에서 UI 발행은 5초에 62–63회(약 12.4–12.6회/초), 보상 애니메이션 DOM은 최대 1개였다. 보상 옵션 전체 ON의 처리량 비용은 기준 대비 약 4–5%였고, OFF에서도 약 1–2% 표본 차이가 있었다. **비용이 0이라고 주장하지 않으며**, 2회 단기 표본으로 일반화하지 않는다. 이전 보고서의 6,000/12,400 수치는 다른 비교의 역사적 기록이다. UI는 고속 실행에서도 매 스텝 갱신되지 않는다.

기존 벤치마크 4개도 다시 통과했다. 9개 맵 각각 500,100스텝의 동기 실행에서 자원 보호/보관 한도를 확인했다. 이 동기 step 처리량은 대화형 처리량과 구분한다. 기존 벤치마크는 E2E와 공유 호스트에서 실행해 절대 성능 비교에는 위 독립 paired 결과를 사용한다. 기존 JSON 기록은 보존하고 새 결과는 `benchmarks/results/v2-*`로 저장했다.

최종 JS는 628.45kB / gzip 148.54kB, 같은 도구로 빌드한 기준 JS는 644.40kB / gzip 148.34kB다. 원시 JS 크기는 감소했고 gzip은 약 0.2kB 증가했다. 500kB chunk 경고는 유지한다. 64×64 SVG 비용을 제거한 변경은 아니며 기존 large-map 렌더링/자원 벤치마크로 회귀를 확인했다.
