**검사일:** 2026-10-26

**독립 검증:** 모든 30종에 대해 JSON의 요소 중복·좌표 범위·포털 쌍·스위치 연결 검사를 통과했고, 실제 엔진 규칙을 Python으로 재현하여 모든 목표를 수집하는 성공 행동열을 재생했다.

## 검사 방법

1. 이전 20개 JSON과 솔루션을 원본 ZIP에서 직접 읽는다.
2. 모든 타일을 인접 이동 방향 그래프로 변환한다. 단방향 타일은 **진입 자유·출발 시 방향 강제**로 해석한다.
3. 포털은 진입 즉시 짝 위치로 1회 이동한다.
4. 정적 상계 분석에서 닫힌 문을 모두 열고, 붕괴 바닥은 무너지지 않았다고 가정한다.
5. 도달 가능한 모든 위치에서 **시작점으로 되돌아갈 수 있는지** 역방향 탐색한다.
6. 스위치나 붕괴 바닥을 사용하지 않고 목표에 접근할 수 있는지 검사해 의도된 기믹의 우회 가능성을 찾는다.
7. 실제 경로 검증은 목표 비트마스크·스위치 상태·붕괴 바닥 비트마스크를 유지하는 재현 시뮬레이터로 수행한다.
8. 일부 30종은 상태 수 때문에 완전 최단 경로 인증 대신 구성적 BFS 경로를 검증했다.

## 특히 중요했던 수정

- **교차로 원정(구 11):** 원래 (11,18) 단방향 타일로 인해 10칸 규모의 일방통행 귀환 불가 지역이 있었다. 문제 타일을 제거하여 정적 귀환 가능성을 회복했다.
- **왜곡된 차원문(구 19):** (5,5)의 아래쪽 화살표가 벽을 가리켰다. 탈출할 수 있는 방향으로 교정했다.
- **최종 시험장(구 20):** (11,7)의 화살표 차단 및 스위치 우회가 있었고, 기존 구조에 부분 수정만 하는 것으로는 재검증이 어려워 지도 전체를 새로 설계했다.
- **붕괴 협곡(구 14):** 전장을 건너뛰던 포털을 제거하고, 붕괴 후 갇힐 위험을 줄이기 위한 먼 안전 우회로를 추가했다. 이 우회로 때문에 붕괴 경로는 *필수*가 아니라 *전략적 선택*이 될 수 있다.
- **붕괴하는 군도(구 18):** 많은 붕괴 타일을 무시하고 통과하는 우회 문제가 있어 구조적으로 새로운 섬/출입 통제 레이아웃으로 교체했다.
- **조심조심 다리(구 4):** 일부 붕괴 후 귀환에 대비해 안전 통로를 추가했다. 이제 붕괴 다리는 위험한 선택 경로다.

## 학습 관점의 중요한 제한

극악 난이도는 사람 기준의 공간 탐색 퍼즐로 설계했으며, **Q-Learning 및 SARSA의 학습 성공률을 검증하거나 높다고 주장할 수 없다.** 64×64까지 지원하도록 프로젝트를 변경하는 일과 극악 난이도에서 표 기반 강화학습이 잘 수렴하는 일은 별개의 문제다.

가장 중요한 개선 권고:

- 맵마다 에피소드 스텝 제한을 명시적으로 설정할 수 있도록 한다.
- 전체 상태(좌표 + 수집한 목표 + 문 상태 + 붕괴 지형) 단위로 반복 순환을 구분한다.
- 학습 중 일반적인 반복은 허용하고, 탐욕 정책 재생에서 확정 반복 순환이면 중지한다.
- 학습 실패율, 방문 상태 수, 평균 수집 목표 수, 패널티를 별도 측정한다.
- 최종 앱에서 실제 TypeScript `GridWorldEnv`를 이용한 30개 솔루션 재생 테스트를 추가한다.

## 향후 제작 기준

**정적 귀환 불가 지점이 0개이고, 성공 경로가 있으며, 필요한 기믹은 의미 있는 접근 제한을 만들고, 가능한 한 안전한 우회로를 제공해야 한다.** 단, 모든 동적 상태에서 탈출 가능한지 최종 판정하려면 상태 탐색 한도 내의 완전 역도달성 분석이 별도로 필요하다.
